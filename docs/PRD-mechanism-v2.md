## 0. 一句话

把对质引擎从"抽取关键词→逐条找命中"升级为 **seed-and-extend 连贯对齐**（PAN/CLEF 抄袭检测的标准范式，源自生物信息学序列比对）：先锚定特异种子，再向两侧延伸出连贯相似段，最后把延伸段作为"调色盘"证物呈堂——证据不再是零散词条，而是**连续、特异、可复核的段落级对应**。

## 1. 338 案病理与机制根因

### 1.1 症状（2026-08-18 实测，HC-20260818-03V3KB）

对 338 期（德皇威廉二世）的判决书暴露四类缺陷：

| # | 症状 | 实例 |
|---|---|---|
| S1 | **公共事实当指纹** | "1914年一战爆发"（任何教材都有）被判 E3 命中 |
| S2 | **自指内容当指纹** | "147-德国为何没变成马克思主义国家"（本播客另一期标题）、"2026年5月5日 UTC"（本单集发布时间戳） |
| S3 | **自我镜像匹配** | SRC1「Facebook」疑似主播自建转载页，7 条 E3 全部命中它——自己抄自己 |
| S4 | **检索预算耗尽** | 会话级 Serper 限额 12 次硬顶，用户感知"轮次偏少且无多轮验证" |

同时暴露的深层缺陷：

| # | 深层缺陷 | 说明 |
|---|---|---|
| D1 | **指纹无长度门槛** | 无 ≥N 字约束，词条级碎片即可成"证据"，不具备复核基础 |
| D2 | **单点命中即成证** | 一个词两边都出现就算 E3，没有"连贯性"要求——这正是与"调色盘"说服力的差距 |
| D3 | **先抽指纹后找源** | 指纹抽取发生在检索之前，抽取时不知道候选源长什么样，无法"先比对再发现证据" |
| D4 | **一对一假设** | 全流程假设单一源，无法处理 AI 时代的"一对多"融合洗稿 |

### 1.2 值得保留的资产

- E1-E5 分级与裁决映射（阈值体系仍然正确，问题在证据生产环节）
- 引文定位四连（精确/模糊/LCS/分句）——将直接复用为"验证"环节
- 母项目 framework_v2 的 **A/B/C 三维度**（句法结构/主干-细节/用意拼接）——本 PRD 将其操作化为算法
- 原始 corpus："willy-nilly tellegram"（电报误拼）在 338 案中被正确抽为 E4_suspect——**抽取直觉在线，缺的是纪律**

## 2. 理论依据（为什么是 seed-and-extend）

### 2.1 PAN/CLEF 文本对齐范式

PAN（Evaluation Lab on Uncovering Plagiarism, Authorship and Social Software Misuse）自 2009 起的抄袭检测竞赛确立 **seed-and-extend** 为文本对齐的主导范式（Potthast et al. 2013 综述：当年全部参赛算法均实现该范式；Wiegmann 2018 给出统一形式模型）：

```
种子 Seeding：token化 → 过滤 → 特征提取 → 序列化 → 匹配
    ↓ 产出：seed = (文1位置, 文2位置) 的锚点对
延伸 Extension：把空间上邻近的种子聚类/合并成极大相似段
    ↓ 产出：aligned passage pair = 连续段落级对应
验证 Verification：对延伸段做语义等价复核，滤除巧合
```

三个关键设计点（本引擎直接继承）：

1. **种子必须特异**（rare）：高频 n-gram（公共事实、套话）在 seeding 阶段就被过滤——对应 338 案的 S1/S2
2. **证据的单位是"延伸段"而非"种子"**：孤立种子不构成证据，只有延伸出的**连续相似段**才算——对应 D2
3. **对齐输出天然是"调色盘"**：this_offset/source_offset/length 的段落对，即用户所说的"一段完整文字的异常表述和对应"

### 2.2 法律标准印证

- **Common errors test（通用错误检验）**：双方作品含相同错误 → 复制的有力旁证（Latman 1990; Balganesh, "Probative Similarity as Proof of Copying"）。E4 的法理出处。
- **Probative similarity（启发式相似）**：法院关注的不是"都写了什么主题"，而是**表达片段的实质性对应**——连贯的、特异的相似，而非散点重合。这正是"调色盘"在中文互联网语境下的说服力来源。
- 母项目 framework_v2 §八 已建立 A/B/C 维度与 verbatim/mosaic plagiarism、substantial/probative similarity 的对应表，继续有效。

### 2.3 一对多融合洗稿（AI 时代新问题）

用户判断：待验证样本可能融合多个源（AI 提炼再创作）。这在 PAN 范式里对应 **多源对齐（multi-source alignment）**：对每个候选源独立跑 seed-and-extend，然后做**跨源拼缝分析**（框架维度 C：语气断裂/逻辑跳跃/知识断层）。338 案若真有源，可能也是这种结构——单源逐条对永远抓不全。

---

### 2.4 证据学边界：不做 AI 文风检测（2026-08-19 用户拍板）

Pangram 等 AI 文本检测工具即便被视为行业标杆，仍存在不可接受的假阳性/假阴性——**风格概率推断永远不能作为司法级证据**。本庭与之划清界限：只采**痕迹证据**（对齐段、错误传播、不可靠性标记），每一件都可回溯到双方原文与抓取记录。检测的是"不可靠性"（叙述的不可靠、论据的不可靠），不是"AI 味"。

## 3. 机制重设计：五阶段流水线 v2

```
立案 → 预审 → 侦查 → 检索 → 【对质 v2：种子锚定 → 延伸 → 验证】 → 宣判
                              └────── 调色盘引擎（本 PRD 核心）──────┘
```

### 3.1 侦查阶段改造：指纹纪律（修 D1/S1/S2）

**抽取前置过滤（确定性规则，LLM 之前）**：

| 规则 | 参数 | 淘汰对象 |
|---|---|---|
| 长度门槛 | 引文 ≥30 汉字（中文）/ ≥15 词（英文），检索词组 ≥50 字 | "1914年一战爆发"类词条 |
| 停用指纹表 | 维基百科首屏级事实、帝王在位年份、世纪大事记 | 公共事实 |
| 自指检测 | 引文是否命中本节目其他单集标题/本单集元数据（标题、时间戳、shownotes） | "147-…"、"2026-05-05" |
| 特异性预检 | 引文归一化后在目标文本外+通用语料（内置常用词表）中出现频度 | 高频表述 |

**LLM 抽取提示词升级**：要求每个指纹必须附"特异性论证"（为什么这不是公共知识——母项目标准："不在维基百科条目首屏"），且只允许 weird_term/rare_case/analogy/joke 四类（data_combo 需 ≥2 个数字的组合，单一日期/年份不再算）；每个指纹的目标侧引文**必须 ≥30 字连续**。

### 3.2 检索阶段改造：预算与多轮（修 S4）

- 检索预算为**案件级**（非浏览器会话级）：默认 60 次共享额度/案；每次新立案重置。用户自有 Key 不受应用侧次数限制，仅受服务商账户额度约束
- 轮次结构：R1 主题（3）→ R2 种子精确（≤10，按种子优先级）→ R3 线报（≤3）→ R4 **延伸验证轮**（≤8，对延伸段中的可疑短语二次检索）——总计可达 24
- **"先比对再发现"（修 D3）**：R1 主题检索抓回候选源全文后，**直接进入对质**；只有对质后仍有大片未覆盖疑区时，才用 R4 换词补搜——检索服务于对齐，而非先验地穷举
- 候选源**自我镜像排除**（修 S3）：源标题/正文与目标作者名、本节目名、目标 URL 同域 → 标记 `mirror:true`，不参与对质，转"归属链佐证"栏

### 3.3 对质阶段 v2：调色盘引擎（核心）

#### 3.3.1 种子锚定（Seeding）

对每个（目标 × 候选源）对：

1. **双语块化**：目标中文按 ~600 字/块、源（英文）按 ~1200 字符/块（母项目 llm_align 参数），带 50% 滑窗
2. **种子=块对**：LLM 判定块对是否构成"特异对应"（同一冷门案例/同一数据组/同一怪词/同一玩笑/同一异常表述）——种子必须自带**双方连续引文**（各 ≥30 字），不再是裸关键词
3. **种子强度分级**：E4_suspect（怪词/错误形式）> E3_strong（冷门案例+数字组合）> E3_weak（可检索但可能公共）——weak 种子不单独成证，只作延伸的起点

#### 3.3.2 延伸（Extension）

对每对种子相邻区域做**扩展比对**（LLM 承担，等价于 PAN 的密度聚类）：

- 从种子两侧各扩 1-2 块，判读该区间是否构成**连贯相似段**（句序对应/例证同序/论证链同构——即框架维度 A/B）
- 产出**对齐段对（aligned passage pair）**：`{目标段引文(≥100字), 源段引文(≥150字符), 对应类型: verbatim|paraphrase|restructure|fabrication, 连贯长度, 维度标注(A/B/C)}`
- **连贯性计量**：一个延伸段覆盖的种子数 + 块跨度。跨度 ≥3 块且含 ≥2 种子的延伸段 = "调色盘级证据"；单块孤立命中 = 降级为"线索"

#### 3.3.3 验证（Verification）

1. **机械验证**（确定性，无 LLM）：每条对齐段的目标/源引文跑引文定位四连（已有能力）——双侧定位失败即弃
2. **语义复核**：对每个延伸段，LLM 独立回答"这两段是巧合的风险"（低/中/高+一句话），双模型时由第二模型承担
3. **调色盘证物**：延伸段以左右分栏+行内高亮渲染（目标段 vs 源段，对应句着色）——判决书与页面的核心展示物，即"可复核的调色盘"

### 3.4 证据分级 v2（继承并细化 E1-E5）

证据单位从"指纹命中"改为"**对齐段**"，每条证据=一个延伸段：

| 证据形态 | 等级 | 触发条件 |
|---|---|---|
| 错误传播段 | **E4** | 对齐段含错误形式对应（corps→court 型）；任何单段即可判"不卫生" |
| 调色盘段（铁证） | **E3+** | 连贯跨度 ≥3 块 且 ≥2 特异种子 且 双侧引文定位通过 且 复核巧合风险=低 |
| 调色盘段（普通） | E3 | 连贯跨度 ≥2 块 且 ≥1 强种子；或 1 强种子+结构对应(B) |
| 结构同构 | E2 | 多个块级对应但特异种子少（论证链/例证序一致，维度 B+） |
| 主题重合 | E1 | 仅话题相同（不单独成证） |
| 直译腔 | E5 | 对齐段中句法级直译（维度 A）≥2 处 |

**裁决映射调整**（唯一改动）：`不卫生 = E4 ≥1 或 E3+ ≥1 或 (E2 且 E3 ≥3)`——E3+（调色盘段）单独即可定案，与"法院认可连贯特异相似"对齐；其余阈值不变。

### 3.5 一对多融合的处理

- 每个 E3+ 对齐段绑定其命中源 → 判决书按源分组展示（"样本 X 的证据"）
- **跨源拼缝检测**（维度 C）：若 ≥2 源各有对齐段，LLM 分析目标文本在源边界处的语气断裂/逻辑跳跃/知识断层，输出"拼缝证物"（C+ 时增强裁决说明，不改变阈值）
- 复用 E4 判定：被融合的源中若含错误且错误被搬用，照样触发 E4（fact-check 项目经验的结构化复用：错误是融合者最难抹除的指纹）

### 3.6b 不可靠性探针（第二证据族，v2.3+）

穿刺文本的目标除同源对齐外，还包括**可靠性审查**（用户命名模式）：

1. **数据的系统化改写**：目标内数字自相矛盾（同一事实两处口径不一）、精度异常（整数编成小数）、单位口径漂移；与候选源数字系统性偏移（千分位、百分比↔绝对值、汇率口径）→ 产出"改写指纹"
2. **他人经历/陈述的不可靠转述**：目标转述某人言论或经历时，与**原始陈述**比对——断章、移花接木、立场反转、细节编造

工程要点：②本质上是"以原始陈述为候选源的对齐"——**复用调色盘引擎**（检索定位原始陈述 → 种子锚定 → 延伸 → 验证），无需新算法。ReliabilityEvidence 作为"叙述不可靠性"栏呈堂，单独不触发"不卫生"（转述失真≠抄袭），但与对齐证据合流时作为 C 维度增强说明。

### 3.6 检索-对质循环（多轮验证，修 S4）

```
循环（最多 3 轮）：
  对质跑完 → 若发现"高覆盖疑区"（目标有长段内容零种子、但周围种子密集）
    → R4 换词检索（针对疑区内容）→ 新候选源入卷 → 重新对质
  直到无新疑区 或 检索预算耗尽
```

判定"疑区"的规则（确定性）：疑区=相邻两个种子间隔 >1500 字的目标区段。

### 3.8 AVECE4 案：高相似候选二次核验与补充取证（2026-08-22）

- 首轮候选上限 10→14，参与相关性排序的候选池 24→40。
- 相似度 ≥75 的具体候选必须进行一次主体关系二次核验；发布日期晚于目标的页面确定性标为同一事件，不能作为来源证据。
- 高相似候选始终触发一次 R7 补充取证；证据不足但已有 E2–E4 具体线索时同样触发。每案最多追加一轮（≤12 条检索式、≤8 个新增候选源），随后重新对质全部材料。
- 证据正文与上下文分字段保存。扩展上下文不得覆盖核心命中句；旧案卷的命中句须在保存的机械上下文中验证为连续原文，否则撤下该侧引文。
- 搜索轮次、检索式数量和补充候选数写入 `searchAudit`，进入判决书局限说明。

## 4. 数据结构与提示词变更

### 4.1 EvidenceItem 扩展

```ts
interface AlignmentEvidence {           // 替代裸指纹命中
  kind: 'alignment_passage';
  targetSpan: string;                    // ≥100 字连续引文（机械定位）
  sourceSpan: string;                    // ≥150 字符连续引文（机械定位）
  spanType: 'verbatim' | 'paraphrase' | 'restructure';
  seeds: { targetQuote: string; sourceQuote: string; seedStrength: 'E4_suspect'|'strong'|'weak' }[];
  coherence: { blockSpan: number; seedCount: number };
  dims: ('A'|'B'|'C')[];                 // 命中的框架维度
  verification: { targetLocated: boolean; sourceLocated: boolean; coincidenceRisk?: '低'|'中'|'高'; note?: string };
}
```

### 4.2 提示词改造要点

- FINGERPRINT_SYSTEM → SEEDING_SYSTEM：块对判定 + 双方连续引文 + 特异性论证
- 新增 EXTEND_SYSTEM：延伸段生成（含 spanType 判别与维度标注）
- FPCHECK_SYSTEM 保留但降级为"验证员"（对延伸段做语义复核），不再承担证据发现
- 所有引文长度约束写进 schema（30/50/100/150 字符级门槛，硬编码在提示词与解析层双重校验）
