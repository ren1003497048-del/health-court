# 卫生法庭 HEALTH COURT*

> 对文化内容进行来源核查的漫画法庭——机制严谨 × 呈现漫画。

[在线使用](https://ren1003497048-del.github.io/health-court/) · [快速开始](#快速开始) · [能力边界](#能力边界) · [致谢](#致谢)

「卫生法庭」之名源自一次被复制的机器转录错误：2025-08-06 英文播客 Breaking History 中的 "health corps, literacy corps"（卫生服务队、扫盲队）被语音识别误作 "health court"，随后被照单翻译为「卫生法庭、扫盲法庭」——历史上从未存在过的机构。一个错误能被复制，就能被发现。

## 这是什么

提交一段文化内容（链接，或不少于 100 字的正文），法庭按证据规程完成五阶段核查——**立案 → 侦查 → 检索 → 对质 → 宣判**——产出可导出、可复核的判决书。

**五种裁决**（本庭绝不输出绝对「卫生」）：

| 裁决 | 含义 |
| --- | --- |
| 不卫生 | 达立案门槛，且发现相同错误传播或结构与罕见材料互相支撑的证据链 |
| 可能不卫生 | 达立案门槛且出现具体对应，但不足以排除巧合 |
| 可能卫生 | 本次可达范围内未发现来源依赖痕迹（附「请持续关注精神卫生」） |
| 不足立案 | 有线索但正式证据不足 2 组，不出具倾向性裁决 |
| 休庭 | 内容不可得，或无可对质的候选 |

机制要点：

- 证据分级 E1–E5（主题 / 结构 / 细节指纹 / 错误传播 / 直译腔），判决由确定性规则计算——LLM 只提供证据材料，引文强制子串定位防幻觉
- 同一来源出现 3 处以上对应即构成「系统性相似」独立证据组——线索级的证据也是证据
- 检索按波次推进：核心 3 源全流程 → 证据不足扩至 8 源 → 上限 14 源，证据凑足即提前终止
- 漫画演出（异议！/ 法槌 / 印章）只读取裁决结果，从不参与计算——关掉动画，每份判决一字不差

## 快速开始

1. 打开[线上版](https://ren1003497048-del.github.io/health-court/)（GitHub Pages，免安装）
2. 「设置」里填入一个模型 API Key（见下节）
3. 核查播客单集时，另配一个语音转录 Key（Groq 可免费注册）
4. 粘贴链接或正文，点「开庭查证」——全程约 10–25 分钟

> 庭审中请勿刷新页面。若意外中断，重新提交同一材料可从断点续跑，已完成阶段不重复消耗额度。

### Key 配置

本站为 BYOK（Bring Your Own Key）架构：Key 只存你的浏览器，本站不经手任何费用。

- **主模型**：任意 OpenAI 兼容端点均可（GLM / DeepSeek / Gemini / OpenAI 等）。订阅套餐类 Key 请按套餐说明选择对应的端点预设；按量付费 Key 亦可，但单案需数十次模型调用，连续核查多篇时按量计费成本会明显偏高，请量入为出。
- **语音转录**（播客单集核查需要）：推荐 Groq（免费注册，额度充裕）；GLM ASR 仅通用端点可用。
- **网页检索**：默认共享额度（每案 60 次），无需配置；想更稳可自填 serper.dev Key。

遇到 GLM 1113「余额不足」报错，多为套餐 Key 配了不匹配的端点——到「设置 → 主模型」切换到与你的套餐匹配的预设即可，应用内亦有指引。

## 隐私与数据流向

纯静态部署（GitHub Pages），无自建服务器、无埋点。Key 与判例只存浏览器 localStorage。你提交的文本、页面或音频按你的配置**直接发送至你所选的第三方服务**（模型端点、Serper / Jina 检索与抓取、Groq / GLM 转录）。使用前请确认相应服务的隐私政策，勿提交敏感内容。

## 能力边界

- **检索不穷尽**：版权墙、未数字化材料不可达。「可能卫生」是本次核查范围内的结论，不是永久证明
- **已发表 ≠ 原创**：发表只证明发布，不证明原创；署名与 attribution 只作注记，不参与裁决
- **输出为文本证据的自动化分析，非法律结论**：「不卫生」等裁决词为游戏化表述，本庭不对内容作者作动机推断
- **证据呈现零黑话**：每条证据 = 人话标题 + 第三人称转述对 + 可点击源链接 + 机械校验过的前后文

## 本地开发

```bash
git clone https://github.com/ren1003497048-del/health-court.git
cd health-court/app
npm install
npm run dev      # 本地开发
npm test         # 单元测试（vitest）
npm run e2e      # 无头 E2E（需 GLM_API_KEY；SOURCE_MODE=seed 用本地种子源）
npm run build    # 构建到 app/dist（base=/health-court/）
```

目录速览：`src/court/` 内核（证据分级、裁决映射、提示词）· `src/pipeline/` 五阶段流水线与波次编排 · `src/providers/` 供应商适配 · `src/ui/` 法庭界面与判决书导出 · `tests/` 单元测试 · `scripts/` 无头 E2E。
