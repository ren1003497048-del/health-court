> [!NOTE]
> 一个诞生于中文播客社区的互联网迷因项目。它借用法庭的程序与角色，对公开发布、带有作者或来源声明的完整文本进行来源核查、证据展示与抗辩，帮助读者判断一份文本的“卫生程度”。

<a id="origin"></a>

## 📜 项目缘起

2026 年 8 月，有网友发现中文世界一档接近百万用户订阅、高频更新的中文播客，系统性地搬运、翻译、洗稿了多个英文世界的公开文本。其中最具戏剧性的一个案例便是 "health court"——有网友发现“独树不成林”播客第 310 期（发布于 2026 年 3 月 1 日）与英文播客 Breaking History - Restless Nation | The Red-Green Alliance: The Making of Modern Iran（发布于 2025 年 8 月 6 日）的讲述顺序高度重叠。其中，原播客在大约 13 分钟提到 "health corps, literacy corps"（卫生服务队、扫盲队），这两个短语在语音转录过程中被错误识别为 "health court"，继而被该中文播客照单讲述为「卫生法庭、扫盲法庭」。

随后，越来越多的社区成员开始核查该播客其他节目，以及主播仲树署名发表的文章、专栏、译者序和其他文本。原本零碎的、转瞬即逝的听感和若有若无的怀疑，逐渐涌现为多份可以逐段对照的材料：相同的叙述顺序、相同的罕见例子、相同的“个人经历”、相同的玩笑与判断，以及相同的错误。

随着证据不断积累，一个以可靠知识讲述者面貌出现的公共文化生产者，开始被社区当作“不可靠的叙述者”重新审视。“卫生法庭”的荒诞语用，也从一个不存在的机构，暗含了一定的文化迷因。

本项目希望延续这种由大众发起、依靠公开材料和共同核验生长起来的社区实践，并将它转化为一种可复用的核验方法。

<a id="why-health-court"></a>

## ⚖️ 为什么是“卫生法庭”

“卫生”“法庭”这一组词在本次社区实践中有了新的内涵和外延。

“卫生”，可以指代一份文本是否清楚标注自己的来源，是否准确转述他人的材料，是否把翻译、改写和个人观点混合成未经说明的“原创讲述”，都可以被视为文本生产中的卫生问题。

这里的“卫生”不是思想纯洁，不是观点审查，也不是要求所有作品都绝对原创。它关心的是来源链是否清楚、引文是否准确、归属声明是否与实际文本相符，以及读者能否追溯一段内容究竟从哪里来。

“法庭”，则指代一种程序。怀疑可能只是起点，相似性也无法自动构成证据。一次严肃的核查过程，既需要提出指控，也应当允许抗辩；既需要展示来源，也需要检查共享的细节；需要区分共同知识、事实转述、合理引用与独特表达的继承；最后还必须诚实说明证据不足之处。

“卫生法庭”不试图也无法替代真正的法庭，它只是借用法庭的角色和程序，把原本可能散落在网络、AI 数据库和不同文化介质当中的材料，打捞并组织成一份可以阅读、质疑和复核的“公开案卷”。

<a id="how-it-works"></a>

## ⚙️ 它如何工作

提交一个受支持的播客单集链接，或一段不少于 100 字、具有明确归属对象的正文，卫生法庭将按照五个阶段完成核查：

> **立案** → **侦查** → **检索** → **对质** → **宣判**

1. **立案**：取得正文，检查内容完整度、发布日期和归属声明；
2. **侦查**：提取叙事结构、罕见例子、怪词、错误与其他文本指纹；
3. **检索**：据此寻找并整理可能的公开来源；
4. **对质**：比较双方原文，检查引文定位、来源关系、时序与合理引用；
5. **宣判**：区分正式证据、辅助线索和未确认相似，生成可导出、可复核的判决书。

> [!IMPORTANT]
> AI 可以协助检索和阅读，但不能凭感觉宣布谁“有罪”。进入正式证据链的正面证据必须回到公开来源和可定位的双侧原文；同一话题、常识、孤立事实和无法复核的模型判断，都不能单独支撑裁决。

### 🏷️ 五种裁决

受付费墙、搜索轮次、模型输入输出不稳定和项目自身局限等因素影响，本庭不输出绝对的“卫生”结论。裁决分为以下五种：

| 裁决 | 含义 |
| --- | --- |
| 🔴 **不卫生** | 达到立案门槛，并发现相同错误传播，或形成结构与多处罕见材料互相支撑的证据链 |
| 🟠 **可能不卫生** | 达到立案门槛且出现具体对应，但现有证据仍不足以排除巧合 |
| 🟢 **可能卫生** | 在本次可达来源和对质范围内，没有发现来源依赖痕迹 |
| 🔵 **不足立案** | 存在线索，但正式证据不足 2 组，不出具倾向性裁决 |
| ⚪ **休庭** | 内容不可得，或多轮检索后仍没有可供对质的候选来源 |

### 🔬 机制要点

- **证据分级**：证据分为 E1—E5，即主题线索、结构同构、细节指纹、错误传播和直译措辞。裁决由确定性规则计算，模型只提供待核验材料。
- **双侧定位**：E3、E4 正面证据必须包含双侧原文，并分别通过机械定位；模型生成但无法在原文中找到的引文只作为线索。
- **系统性相似**：同一直接来源中，至少 3 组不同的双侧原句定位通过，并排除具体引用、公共新闻事实和倒序来源后，才会合并为 1 组“系统性相似”证据；原线索不重复计数。
- **分波检索**：先核查核心候选源，证据不足时逐步扩展，达到证据门槛后提前终止，避免无边界消耗。
- **演出与裁决分离**：“异议”、印章和漫画式庭审演出只读取裁决结果，从不参与证据计算；关闭动画不会改变判决内容。

<a id="quick-start"></a>

## 🚀 快速开始

1. 打开[线上版](https://ren1003497048-del.github.io/health-court/)；
2. 在“设置”中填写主模型 API Key；
3. 按所选模型配置搜索通道；
4. 核查没有公开文字稿的播客时，另行配置语音转录 Key；
5. 粘贴链接或正文，点击“开庭查证”。

完整庭审通常需要 10—25 分钟（甚至更久），具体取决于文本长度、候选源数量、网络和第三方服务响应速度。

> [!TIP]
> 建议在网络访问稳定、模型额度充足的环境中使用，以降低中断和重复调用的成本。部分模型可能对特定材料不予召回或触发敏感词限制。

> [!WARNING]
> 庭审中请勿刷新页面。若意外中断，重新提交同一材料可以从快照续跑，已经完成的阶段不会重复消耗额度。

### 🔑 Key 配置

本站采用 BYOK（Bring Your Own Key）架构。Key 只保存在当前浏览器，项目不代收费用，也不提供共享密钥。

- **主模型**：支持 GLM、DeepSeek、Gemini 及 OpenAI 兼容端点。一次完整庭审可能产生数十次模型调用，请留意所选服务的额度与计费方式。
- **网页检索**：GLM、Gemini 可以使用模型内置检索；选择 Serper 时必须填写自己的 Serper API Key。DeepSeek 和普通 OpenAI 兼容端点没有本项目可调用的内置检索，需要配合 Serper 使用。
- **语音转录**：仅在播客页面缺少正文时使用。可选择 Groq Whisper 或 GLM ASR，实际免费额度与限制以服务商当前政策为准。
- **页面抓取**：Jina Key 为可选项，用于改善部分网页的正文获取效果。

遇到 GLM 1113“余额不足”报错，通常是套餐 Key 与接口端点不匹配。请前往“设置 → 主模型”，切换到与你的套餐对应的端点预设。

<a id="privacy"></a>

## 🔒 隐私与数据流向

本站为部署在 GitHub Pages 上的纯静态应用，没有自建业务服务器，也不设置用户账户。

API Key、设置和本地判例保存在浏览器的 `localStorage` 中。你提交的文本、网页或音频会按照当前配置，直接发送至所选的模型、搜索、抓取或转录服务。

> [!CAUTION]
> 使用前请确认相应第三方服务的隐私政策，不要提交私人通信、未公开作品或其他敏感内容。

<a id="boundaries"></a>

## 🧭 能力边界

- **检索无法穷尽**：版权墙内、尚未数字化或未被搜索引擎索引的材料可能无法到达。“可能卫生”只代表本次可达范围内未发现问题，不是永久证明。
- **发表不等于原创**：公开发表只证明发布行为，不证明内容原创；署名和来源声明会进入案卷，但不会自动短路裁决。
- **相似不等于来源依赖**：同题材、共同知识、公共事实和孤立措辞不能单独构成正式证据。
- **自动分析可能出错**：模型可能遗漏候选源或误解语义，因此判决书同时提供原文、链接、线索和核查局限，供读者自行复核。
- **输出不是法律结论**：“不卫生”等裁决词属于游戏化表达。本项目不判断作者动机，也不替代著作权认定或司法程序。

<a id="local-development"></a>

## 🛠️ 本地开发

```bash
git clone https://github.com/ren1003497048-del/health-court.git
cd health-court/app
npm install
npm run dev      # 本地开发
npm test         # 单元测试
npm run e2e      # 无头 E2E，需要相应 API Key
npm run build    # 构建到 app/dist
```

**目录速览**

- `src/court/`：证据分级、裁决映射与提示词
- `src/pipeline/`：五阶段流水线与波次编排
- `src/providers/`：模型、搜索与转录服务适配
- `src/ui/`：法庭界面与判决书导出
- `tests/`：单元测试
- `scripts/`：无头 E2E 与辅助脚本
