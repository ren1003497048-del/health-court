# 卫生法庭 HEALTH COURT*

> 对文化内容进行来源核查的漫画法庭。**机制严谨 × 呈现漫画。**
>
> 「卫生法庭」之名源自一次被复制的机器转录错误：2025-08-06 英文播客 Breaking History 中的
> "health **corps**, literacy **corps**"（卫生服务队、扫盲队）被语音识别误作 "health court"，
> 随后被照单翻译为「卫生法庭、扫盲法庭」——历史上从未存在过的机构。
> 一个错误能被复制，就能被发现。

## 这是什么

用户提交一段文化内容（链接或 ≥100 字正文），法庭依照司法级证据规程完成五阶段流程：
**立案（取证）→ 侦查（画像/指纹/群众线报）→ 检索（波次扩张）→ 对质（结构对齐/指纹验证/证据检定）→ 宣判**，
给出裁决与可导出的判决书。

**五种裁决**（本庭绝不输出绝对「卫生」——检索不穷尽，未发现≠证明清白）：

| 裁决 | 含义 |
| --- | --- |
| 不卫生 | 正式证据达立案门槛，且发现相同错误传播或结构+罕见材料互相支撑的证据链 |
| 可能不卫生 | 达立案门槛且出现具体对应，但现有证据不足以排除巧合 |
| 可能卫生 | 本次可达来源与对质范围内未达阈值的来源依赖痕迹（附「请持续关注精神卫生」） |
| 不足立案 | 有线索但正式证据不足 2 组，不出具倾向性裁决 |
| 休庭 | 内容不可得，或多轮检索后无可对质候选 |

## 机制要点

- **证据分级 E1–E5**（继承母项目「播客抄袭鉴定」方法论：主题/结构/细节指纹/错误传播/直译腔）
- **判决由确定性规则计算**（`src/court/evidence.ts`），LLM 只提供证据材料；引文强制子串定位防幻觉
- **立案门槛**：正式证据 ≥2 组（2026-08-23 拍板 3→2：2 组成立已说明系统性、关联性相似）
- **同源系统性相似**：同一候选源 ≥3 处对应（含线索级）自动产出独立证据组——「线索级的证据也是证据」
- **引用合规三分类**（v3.3）：具体标注→转注记；泛化承认→降格线索；未声明→正常证据。已发表≠原创，署名只作注记不参与裁决
- **波次检索**（v3.5）：按「相似度+源形态+指纹词命中」排序，核心 3 源全流程 → 证据不足扩至 8 源 → 仍不足并入补检索（硬上限 14 源）。≥2 组即提前终止——实锤案 10-15 分钟，不再 21 源盲扫
- 漫画演出（异议！/判决锤/印章）只读取裁决结果，从不参与计算——把动画全关掉，每份判决一字不差

## 快速开始

1. 打开 [GitHub Pages 线上版](https://ren1003497048-del.github.io/health-court/)（或本地 `npm run dev`）
2. 「设置」填入模型 API Key（默认 GLM；支持 DeepSeek / Gemini / 任意 OpenAI 兼容端点）
3. 需要核查播客单集时，另行配置语音转录 Key（推荐 Groq whisper-large-v3，免费注册）
4. 「开庭」粘贴链接或正文 → 等待五阶段走完 → 导出判决书 HTML/JSON

### 配置什么 Key？怎么注册？（推荐顺序）

本庭是 BYOK（Bring Your Own Key）架构——你填自己的 Key，本站不经手任何费用。**按成本从低到高推荐：**

**① 主模型（必配）——首选订阅套餐类，不建议按量付费 Key**

| 推荐度 | 方案 | 注册 | 成本 |
| --- | --- | --- | --- |
| ⭐ 首选 | **GLM Coding Plan 套餐**（含在 Codex/Claude Code 等编程订阅里的 GLM 额度） | [bigmodel.cn](https://open.bigmodel.cn) 开通 Coding Plan | 包月，单案核查（数十次模型调用）摊薄后近零边际成本 |
| 备选 | GLM 按量付费（开放平台充值） | 同上 | 单案约几毛到几元——连续核查多篇时成本偏高，不推荐作为主力 |
| 备选 | 已有的 ChatGPT Plus / Claude Pro / Gemini 订阅对应 API 试用额度 | 各自平台 | 注意：网页订阅与 API 额度是两回事，多数不含大额 API |

> 关键提示：如果你手上是 **GLM Coding Plan 套餐 Key**，设置页必须选「**Coding 套餐端点**」预设（`open.bigmodel.cn/api/coding/paas/v4`）；选通用端点会报 1113「余额不足」。反之，按量付费 Key 选「通用端点」。

**② 语音转录（核查播客单集才需要）——推荐 Groq 免费档**

| 推荐度 | 方案 | 注册 | 说明 |
| --- | --- | --- | --- |
| ⭐ 首选 | **Groq whisper-large-v3** | [console.groq.com/keys](https://console.groq.com/keys) 免费注册 | 免费额度对本庭用量绰绰有余 |
| 不推荐 | GLM ASR | — | 只有通用端点；Coding Plan 套餐 Key 调用必报 1113 |

**③ 网页检索（可选）——默认共享 Serper 额度（每案 60 次），一般无需配置**

想要更快更稳可自填 [serper.dev](https://serper.dev) Key（免费注册送额度）；或切换为主模型内置检索。

> 想省事？只配 ①（GLM Coding Plan）+ ②（Groq）两个免费/包月渠道，即可完整使用全部功能。**不建议为用本庭单独购买按量付费 API**——单案调用次数多，按量计费的总成本会明显高于包月方案。

### 使用注意

- 一案全流程约 10-25 分钟（取决于是否需转录音频）；**庭审进行中请勿刷新或断网**——本庭已内置阶段快照，中断后重新提交同一材料可从断点续跑，但正在进行的单阶段（如转录中）仍需重做该阶段
- 案卷与判例只存你的浏览器 localStorage；换浏览器/清缓存会丢历史（可先导出判决书 JSON 归档）

## 能力边界（先读再用）

- **检索不穷尽**：版权墙、未数字化材料、未被索引的内容本庭不可达。「可能卫生」是本次核查范围内的结论，不是永久证明
- **已发表≠原创**：发表渠道只证明发布，不证明原创。署名与 attribution 只作注记，不参与裁决
- **输出为文本证据的自动化分析，非法律结论**：「不卫生」等裁决词为游戏化表述；本庭不对内容作者作动机推断
- 证据呈现零黑话：每条证据=人话标题+第三人称转述对+可点击源链接+前后文对照（机械校验逐字真实）

## 目录

```
PRD.md            产品需求文档（含方法论、实测记录、移植映射）
app/              应用（React + Vite + TS，纯静态 BYOK）
  src/court/      内核层：证据分级、裁决映射、文本工具、提示词（可在 Node 无头运行）
  src/pipeline/   五阶段流水线 + 波次检索编排（waves.ts，UI 与无头测试共用）
  src/providers/  供应商适配：GLM / DeepSeek / Gemini / OpenAI 兼容 / Groq ASR / Serper / Jina 抓取
  src/ui/         法庭界面 + 判决书导出
  tests/          单元测试（vitest）
  scripts/        无头 E2E（310 期复现 E4）
```

## 隐私与数据流向

本站纯静态部署（GitHub Pages），无自建服务器、无埋点。API Key 与判例只存你的浏览器 localStorage。文本、来源页面或音频会按你的配置**直接发送至你所选的第三方服务**：

- 模型推理：你配置的模型端点（如 open.bigmodel.cn / api.deepseek.com / generativelanguage.googleapis.com / api.openai.com）
- 网页检索与抓取：Serper / Jina（可自填 Key）
- 语音转录：Groq 或 GLM ASR（播客单集核查时）

使用前请确认相应服务的隐私政策，避免提交敏感内容。
